# Media research and manual sending

Describe participation as voting on bills (support, oppose or abstain), not posting comments or sharing written views. Crossbench does not offer a commenting feature. Media feedback is a request for a reply to Jeff, not a claim that site users can comment.

The protected `/admin/media` page holds 44 research contacts: the existing 26 plus 18 new routes researched on 8 September 2026. Twenty-four unique email addresses have public-source evidence. This is not delivery verification or consent to contact.

`src/lib/media-research.json` records source URLs, checked dates, route types, pitch angles and cautions. Existing contact IDs are preserved. An email must match its evidence, have a valid non-future checked date and an HTTPS source to be labelled publicly listed. Evidence older than 90 days is labelled overdue for review. Rechecking requires reviewing the cited source, not merely changing its date.

Sending is admin-triggered, one contact at a time. Select a draft, choose **Review single email**, review the exact recipient/from/reply-to/subject/body, tick the approval checkbox, then choose **Confirm and send one email**. Cancelling, copying, downloading, navigating or changing the selected contact never sends an email. Changing contacts discards approval. No bulk sender, background queue, automatic retry, recipient override, CC or BCC is provided. The command-line script remains preview-only and rejects all delivery flags.

`GET /api/admin/media/send?contactId=…` checks availability and history without writes. `POST /api/admin/media/send` requires admin authentication, an allowed same-site Origin, a bounded JSON object naming exactly one contact, explicit confirmation and the current server-generated draft digest. Recipient and contents are resolved server-side; changed drafts and stale/missing source evidence fail closed. Existing Resend configuration is reused; no new provider or credential is required.

The existing `OutreachEmailLog` has two additive nullable audit fields: `sentBy` and `textBody`. A unique campaign/address record is reserved before calling the provider. Legacy media records are checked case-insensitively across campaigns. Existing sent, pending, failed and skipped/withheld records block repeats; conflicts and unknown outcomes are never automatically retried. Provider requests use a stable per-record idempotency key. `SENT` means provider acceptance, not confirmed inbox delivery. `PENDING` can mean in progress or an uncertain outcome; reconcile the provider record before any further action. This page deliberately offers no force/resend override.

Drafts briefly introduce Jeff as the person behind Crossbench, explain the idea, disclose that it is extremely early days and broader outreach/marketing has not begun, and invite honest feedback and optional support. They distinguish newsroom greetings from named journalists, reference the recipient's outlet and state that participation is self-selected, not representative polling. Individual pitch angles remain research notes on the contact cards rather than internal briefing instructions pasted into the introductory email. Review current facts, contact guidance, previous outreach/opt-outs and shared-newsroom duplication before each confirmation. Publicly listed addresses must never automatically become approved recipients.

Validation: `npm test` includes source-age, escaping, CLI no-send, admin/Origin/input validation, exact drafts, duplicate/concurrent confirmations, history failures and uncertain delivery outcomes. Run lint and the full build before the existing GitHub release workflow. `node scripts/test-media-send-db.cjs` tests the additive migration and real PostgreSQL concurrency in a disposable loopback-only Docker container using the existing `postgres:16-alpine` image; it never uses a production database or email provider.

After building, `node scripts/test-media-browser.cjs` runs an isolated loopback server with ephemeral in-memory test authentication, blocks external browser requests and mocks all email-send responses. It checks desktop/mobile search, filters, drafts, CSV/copy, confirmation/cancellation, contact changes, duplicate clicks, sent/uncertain states and anonymous page/API rejection. Set `MEDIA_TEST_CHROMIUM` to an installed Chromium executable when needed. It does not use production credentials, a production database or real email delivery.
